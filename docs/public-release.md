# 공개 준비

## 현재 반영 상태

- 실제 환경변수 파일, 개인 키·인증서 저장소, 로그, DB 파일·백업을 Git에서 제외한다. `.env.example`은 사용법을 안내하는 예제만 둔다.
- `backend/bin/` 컴파일 산출물은 추적에서 제외했다. Gradle Wrapper JAR는 실행에 필요한 배포 도구이므로 유지한다.
- 공개 문서의 개인 PC 경로는 일반적인 예시로 바꾸고 개인 라이브러리 링크를 제거했다.
- `.local-tools/`에는 로컬 도구와 환경변수 백업이 있다. 계속 Git에서 제외한다.

## 공개 전 검사

프로젝트 루트에서 실행한다.

```powershell
node scripts/check-public.mjs
node scripts/check-public.mjs --history
```

첫 명령은 Git이 추적하는 파일과 새로 추가할 수 있는 파일의 현재 내용을 확인한다. 두 번째 명령은 로컬 브랜치·태그·원격 추적 브랜치에서 접근 가능한 과거 커밋과 작성자/커미터 이메일을 확인한다. 값은 출력하지 않고 파일·위치·규칙만 출력한다. 바이너리 내용과 알려지지 않은 형식의 비밀 값은 완전히 검사하지 못한다.

이 검사에서 찾지 못했다는 사실이 비밀 정보가 전혀 없다는 보장은 아니다. 테스트용 키도 운영에서는 사용하지 않는다.

## 기존 이력 처리 상태

사용자가 원격 저장소를 삭제·재생성한다. 현재 작업에서는 로컬 Git 이력을 삭제하거나 다시 쓰지 않았고 커밋·푸시도 하지 않았다.

**원격 저장소만 다시 만들어도 로컬 기존 이력은 사라지지 않는다.** 지금 로컬 브랜치를 그대로 push하면 과거 개인정보가 다시 올라갈 수 있다. 새 저장소로 연결하기 전에 로컬 이력 처리 방법을 별도로 확정해야 한다. 기존 이력을 보존하려면 공개할 새 작업 폴더에서 깨끗한 이력을 시작하는 방식도 가능하다.

새 커밋에 사용할 이메일은 GitHub Settings의 Emails에서 본인 noreply 주소를 확인하고 프로젝트 범위에서 설정한다. 추측한 이메일이나 전역 설정 변경은 사용하지 않는다.

```powershell
git config --local user.email '<GitHub에서 확인한 noreply 주소>'
```

소스 공개와 서버 외부 배포의 검증 범위는 다르다. 현재 로컬 DB 예제 비밀번호를 운영에서 재사용하지 않고, 외부 배포 시 HTTPS·Secure 쿠키·로그인 시도 제한·토큰 폐기 정책을 검토한다.
